ALGORITHM GUIDE

Complexity Reference

Operation Heap File Sequential File
Key Search (Probes) O(n) [avg n/2] O(log₂ n) [Binary Search]
Search Block I/O avg b/2 disk blocks ⌈log₂ b⌉ disk blocks
Insert Record O(1) (2 I/Os: append) O(n) (b I/Os: search + record shift)
Delete Record O(n) (b/2 read + 1 write) O(n) (b I/Os: search + record shift)
Ordered Scan / Range O(n log n) (needs sort) O(n) (b sequential I/Os)
*b = total disk blocks; n = total records. Sequential utilizes Binary Search over sorted key blocks.

DBMS CONCEPT LAB

Learn the storage model

Understand the concepts before experimenting with the simulator.

01

File Organization

File organization describes how records are arranged and stored in secondary storage.

02

Heap Files

A heap file does not maintain records in key order. New records are typically appended.

03

Sequential Files

A sequential file maintains records according to a selected ordering primary key.

04

Disk Blocks

Databases transfer data between secondary storage and memory in blocks or pages. FILEFORGE models this visually.

05

Searching

Searching can require examining multiple records. The simulator counts comparisons and simulated block accesses.

06

Insertion

Heap insertion appends a record in O(1), while sequential organization must maintain key ordering in O(N).

07

Deletion

Deletion requires locating the record and updating the file representation via tombstones or compaction.

08

Block Capacity

Changing block capacity lets you observe how the number of storage blocks and internal fragmentation change.

09

Real Applications

Different storage organizations are selected depending on workloads such as high-frequency insertion or ordered access.

USER MANUAL

How to use FILEFORGE

A complete walkthrough of every control, the playback engine, and how to read the output.

QUICK START

Run your first simulation in 4 steps

  1. Load data. Open Simulator and click ⟳ Generate Dataset for a random set of records, or ↑ Import and choose sample_dataset.json from the project folder.
  2. Pick a strategy. In the Configuration card choose a Search Strategy (start with Binary Search or Dual Race Mode) and set the Animation Speed.
  3. Start a search. Type an existing ID into RECORD ID and press ⌕ Search. The playback bar arms itself and shows Searching for Record <id>.
  4. Step through it. Press ▶ to auto-play, or › to advance one probe at a time and read the explanation printed for each step.
RECORD OPERATIONS

Insert, Search, Delete

  • + Insert — needs all four fields (ID, Name, Department, Marks 0–100). The record is appended to the end of the Heap file and placed in sorted key position in the Sequential file. Duplicate IDs are rejected.
  • ⌕ Search — only the RECORD ID field is used. This does not run instantly; it builds an animation queue you drive with the playback bar.
  • × Delete — only the RECORD ID field is used. The record is removed from both files and the blocks are re-rendered so you can watch records shift.
PLAYBACK BAR

Controlling the animation

  • ▶ / ❚❚ — play or pause the probe sequence at the selected speed.
  • › — advance exactly one probe. Best for viva demos and for counting comparisons by hand.
  • ‹ — step backward to re-examine the previous probe.
  • Reset — clear the current run and unhighlight all blocks. The data itself is not deleted.
  • The progress bar and the n / total counter show how far through the probe sequence you are.
SEARCH STRATEGIES

What each mode demonstrates

StrategyHeap FileSequential FileUse it to show
Binary Search Linear scan, O(N) Binary search, O(log₂ N) The core performance gap between the two organizations
Dual Race Mode Linear scan Binary search Both heads moving in lock-step, with a winner summary
Sequential Scan Linear scan Linear scan That sorting alone gains nothing without the right algorithm
Ordered Scan Linear scan Linear scan, early stop Early termination once a key larger than the target appears
Binary Search and Dual Race Mode display [L], [MID] and [R] pointer badges, and dim every record outside the active partition.
READING THE BLOCKS

Storage view

  • BLOCK CAPACITY slider (2–8) sets how many records fit in one disk block. Lower it to create more blocks and more I/O; raise it to see fewer, fuller blocks.
  • FULL (4/4) in green means the block is packed; PARTIAL (2/4) in amber means it has free slots.
  • Dashed outlines are empty slots — this is internal fragmentation.
  • Packing Factor = active records ÷ total allocated slots × 100%.

TROUBLESHOOTING

Common issues

  • "Please enter all record details" — Insert needs all four fields; Search and Delete need only the ID.
  • Nothing animates after pressing Search — the run is armed but paused. Press ▶ or ›.
  • "Record already exists" — primary keys are unique; pick another ID.
  • Import does nothing — the file must be valid JSON exported by ↓ Report / export, with heap, sequential and blockSize keys.
  • Colours look wrong — use ◐ Toggle Theme at the bottom of the sidebar to switch between dark and light mode.
